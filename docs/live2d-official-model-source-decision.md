# Aris Live2D 正式模型来源与授权决策

## 目的

本文件用于收束 `v2` 之后正式模型阶段里最前置的一个问题：

- 正式模型从哪里来
- 哪些资源可以只用于调试
- 哪些资源可以长期作为正式基线
- 资源应该如何存放与分发

这不是运行时实现细节，而是正式模型阶段的前置决策。若这一步没有定清，后面的 `profile`、`motionMap`、`parameterMap`、正式模型接线都容易建立在错误前提上。

## 现有证据

当前仓库里已经存在比较明确的倾向：

1. `docs/live2d-research.md` 明确建议：
   - 不要把正式模型直接塞进 npm 包中
   - 更稳妥的方向是“本地资源目录”或“后续独立资源包”
   - 调试阶段可以使用官方 sample model 验证 runtime
   - 正式随插件分发时，应使用自己拥有明确授权的模型资源
   - 不要默认把网上找到的 VTuber / 二创 Live2D 资源并入仓库

2. `docs/live2d-mvp-setup.md` 已经把“正式授权内置模型资源”列为 MVP 仍未包含项，说明当前阶段并没有把临时模型视为长期资产。

3. `docs/live2d-official-model-checklist.md` 和 `docs/live2d-official-model-next-steps.md` 都已把“模型来源与授权”列为正式模型阶段的第一前置条件。

## 决策问题

正式模型阶段需要回答 4 个问题：

1. 正式模型是否允许入仓。
2. 正式模型是否允许随插件一起分发。
3. 若不允许入仓，资源应放在本地目录还是独立资源包。
4. 临时调试模型与正式模型的边界如何定义。

## 候选方案

### 方案 A：继续长期使用 sample model

含义：

- 继续拿官方 sample model 或其他调试模型当长期正式模型
- 直接围绕它补完正式模型阶段能力

优点：

- 最快
- 几乎不需要新的资产整理

缺点：

- 许可与著作权边界不适合作为长期默认方案
- 形象不稳定，难以形成真正的“爱丽丝正式模型”
- 后面一旦切换模型，动作名、表情名、参数名都可能再次整体迁移

判断：

- 只适合作为调试过渡，不适合作为正式基线

### 方案 B：正式模型外置，本地路径接入

含义：

- 代码仓库不直接携带正式模型资产
- 正式模型放在老师本地可控目录
- 运行时通过 `live2dModelBase` 指向本地 `model3.json`

优点：

- 最贴合当前许可风险控制
- 不污染 npm 包与代码仓库
- 可以最快开始正式模型阶段的运行时接入
- 与当前配置结构兼容，改动最小

缺点：

- 资源复制、备份、换机需要额外管理
- 新环境初始化步骤会比“仓库即开即用”多一点

判断：

- 这是当前阶段最稳妥、最现实的默认方案

### 方案 C：正式模型入仓并随插件分发

含义：

- 把正式模型放入仓库，例如 `packages/dsh-aris/assets/live2d/aris/`
- 插件安装后即可直接使用

优点：

- 使用体验最好
- 文档与环境初始化最简单
- 运行与资源版本天然同步

缺点：

- 只有在授权非常明确时才安全
- 一旦授权边界出问题，风险最大
- 仓库与发布产物体积也会增加

判断：

- 只能作为“明确可分发授权已落实”后的升级形态，不应作为当前默认前提

### 方案 D：正式模型拆到独立资源包

含义：

- 代码插件继续只负责 runtime
- 模型、贴图、motions、expressions 独立为资源包或单独分发单元

优点：

- 代码与资产职责清晰
- 后续更适合做多资源版本管理
- 比“直接塞进主包”更可控

缺点：

- 当前阶段实现成本高于本地外置路径
- 需要额外设计资源包发布、版本与安装路径

判断：

- 适合作为中后期演进方向，不是当前最小落地方案

## 默认推荐决策

在老师没有给出新的授权前提之前，默认采用：

1. **sample model 只用于 runtime 验证，不作为正式模型基线。**
2. **正式模型默认不直接入仓，不直接绑进 npm 包。**
3. **正式模型的首选落地方向是“本地资源目录 + `live2dModelBase` 外置配置”。**
4. **只有当授权明确允许时，才考虑升级到“入仓分发”或“独立资源包”。**

这是当前证据下最稳妥的工程默认值。

## 对当前仓库的直接影响

采用上述默认决策后，后续推进应遵循：

1. `docs/live2d-official-model-checklist.md` 中的“资产目录约定”优先按“外置路径”理解。
2. `docs/live2d-official-model-next-steps.md` 中 `Phase 1` 的“确认资产来源”默认以“本地可控正式模型”收束。
3. 后续在 `index.ts` 扩展 `live2dProfile` / `live2dMotionMap` / `live2dExpressionMap` / `live2dParameterMap` 时，不假设正式模型一定入仓。
4. README 与配置示例应同时保留“外置资源路径”方案。

## 需要老师最终拍板的点

虽然默认推荐已经明确，但仍有 3 个点需要老师给出最终 source of truth：

1. 正式模型打算走哪条来源线：
   - `现成授权模型`
   - `约稿新模型 + Rig`
   - `已有立绘拆件重做 Rig`

2. 近期目标是否只要求“老师本机长期可用”，还是已经要求“可随插件一起分发”。

3. 如果短期内没有明确可分发授权，是否接受“正式模型先外置、本地路径接入”作为阶段性正式方案。

## 当前拍板结果

当前已确认的 source of truth：

1. 正式模型来源线：`现成授权模型`
2. 近期目标：`先保证老师本机长期可用`
3. 阶段性正式方案：`接受先外置、本地路径接入`

这意味着：

- 当前不用等待“随插件一起分发”的授权链路才能继续实现
- `live2dModelBase` 外置配置将作为正式模型首阶段的默认接法
- 后续若授权扩展到可分发，再考虑升级为入仓分发或独立资源包

## 当前建议

如果马上要推进下一步，建议按下面顺序执行：

1. 先接受“正式模型先外置、本地路径接入”作为默认基线。
2. 再开始补 `profile + mapping` 这套配置协议。
3. 等资源授权明确后，再决定是否升级成入仓分发或独立资源包。

## 一句话总结

当前最合理的默认结论是：**sample model 只负责打通链路，正式模型默认走外置、本地可控、授权明确的路径；不要把临时调试资源直接升级成长期正式资产。**
