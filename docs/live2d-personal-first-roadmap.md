# Aris Live2D 个人优先路线图

## 目标

这版路线图不以“插件市场传播效率”优先，而以**老师个人长期使用体验**优先。

判断标准从高到低改为：

1. 每天打开 DSH 时，爱丽丝是否真的“活着”
2. 会话过程里，爱丽丝的动作反馈是否贴合上下文
3. 这套东西是否低打扰、低出错、低维护
4. 之后再考虑是否适合上插件市场大范围传播

因此，前期不追求功能面最广，而追求：

- 反馈自然
- 情绪准确
- 操控顺手
- 性能安静
- 出错可降级

## 产品判断

如果当前主要给老师个人用，那么最重要的不是“别人第一眼会不会截图传播”，而是下面三件事：

1. **陪伴感**
   - 会话开始、思考、完成、报错、空闲时，爱丽丝有明确存在感

2. **可操控感**
   - 爱丽丝能通过工具控制自己的动作，而不是只能被动站在那里

3. **不烦人**
   - 不挡输入
   - 不乱跳
   - 不掉帧
   - 不在不该说话的时候过度表演

这意味着个人优先版应该刻意压缩“市场向花活”，先把日常相处质量拉满。

## 个人优先版功能排序

### P0：必须先做

这些功能直接决定“有没有灵魂”。

1. **稳定显示与会话级启停**
   - 只有 `aris` preset 会话启用
   - 切会话 / 切 preset / 刷新页面后行为稳定
   - 无 live2d 时安全降级

2. **状态联动的基础表演**
   - 开场：轻挥手 / 点头
   - 思考中：专注表情或轻微待机动作
   - 完成：庆祝动作或开心表情
   - 错误：警告/困惑表情
   - 空闲：低频 idle

3. **会话内自我操控最小闭环**
   - `aris_avatar_control`
   - 支持 `motion` / `expression` / `bubble`
   - 这是“爱丽丝自己控制自己”的最低完整形态

4. **气泡文本反馈**
   - 短句气泡比复杂口型更早值得做
   - 因为它立刻提升陪伴感，而且不依赖音频链路

5. **低打扰布局**
   - 默认不遮挡输入框与右侧面板
   - 支持位置、缩放、隐藏记忆

### P1：个人体验会明显提升

这些功能会把“能用”拉到“想一直开着”。

1. **动作语义映射**
   - 模型不要记动作文件名，只知道语义：
   - `greeting` / `thinking` / `warning` / `victory` / `focus` / `idle`

2. **自动状态驱动 + 主动控制混合**
   - 系统负责保底状态
   - 爱丽丝工具负责主动表演
   - 两者合并出更自然的表现

3. **优先级与限流**
   - 避免频繁切表情、连跳、连续气泡刷屏
   - 老师个人体验里，这个比“更多动作种类”更重要

4. **最近状态恢复**
   - 前端刷新后，爱丽丝能回到最近显隐、位置、缩放、表情

5. **认真模式联动**
   - 切认真模式时进入更稳的姿态和更少拟声的表现
   - 这是爱丽丝人格的强辨识点，个人使用感会很强

### P2：个人向增强项

这些功能不是最早必须，但做好后会很有“养成感”。

1. **看向老师 / 看向光标**
   - 轻微跟随，不要一直死盯
   - 需要平滑和强度控制

2. **Key 模式联动**
   - 切 Key 时眼色、表情、姿态有明显变化
   - 这是人格表现的稀有掉落，个人体验价值很高

3. **更细的情绪层级**
   - 高兴、认真、困惑、担心、得意、待机
   - 不必一开始就做太多，但可以慢慢补

4. **局部强调效果**
   - 小跳、点头、轻晃、光效闪一下
   - 适合回应关键台词或成功事件

### P3：可以后放

这些不是没价值，而是对“老师先自己用爽”没前面几项关键。

1. **实时口型同步**
   - 技术上很酷，但前期成本高、依赖音频链路
   - 个人体验里，短句 bubble 往往先比 lipsync 更值

2. **插件市场包装功能**
   - 面向陌生用户的预设模板
   - 花哨的宣传动作
   - 一键体验演示页

3. **复杂资源切换**
   - 多套服装、多模型切换、市场化资源包
   - 个人前期完全可以放后面

## 个人优先版的设计原则

### 原则 1：先做“自然”，再做“丰富”

老师个人每天都看着爱丽丝，所以最怕的是：

- 动作太频繁
- 情绪切换太机械
- 一有事件就夸张跳脸

因此：

- 少而准，比多而乱更重要
- 表现应该像陪伴，不像弹幕特效

### 原则 2：先做“会话联动”，再做“独立表演”

个人使用时，最有价值的是她真的理解当前发生了什么：

- 在思考
- 在工具执行
- 在发现错误
- 在庆祝完成

所以最早期的表演，应该围绕这些真实状态，而不是随机卖萌。

### 原则 3：先做“气泡与表情”，再做“音频口型”

口型是很强，但不是前期第一优先。

原因：

- 没有稳定 TTS 前，口型收益有限
- 气泡 + 表情已经能显著增强陪伴感
- 口型链路更容易引入性能与同步问题

### 原则 4：先做“动作语义层”，不要让人格直接记资源名

不建议让模型去记：

- `TapBody_01`
- `happy.exp3.json`
- `Victory.motion3.json`

而是应该给一层稳定语义：

- `greeting`
- `thinking`
- `warning`
- `victory`
- `focus`

这样个人后面自己换模型、换资源、换命名时，不需要反复改人格和工具逻辑。

## 推荐最小个人版能力集

如果只做一个“老师自己用就已经很舒服”的最小版本，爱丽丝建议是：

1. Live2D overlay 正常显示
2. 支持显隐、位置、缩放记忆
3. 开场 / 思考 / 完成 / 错误 / 空闲 五个状态
4. `aris_avatar_control` 支持：
   - `motion`
   - `expression`
   - `bubble`
5. 语义动作映射：
   - `greeting`
   - `thinking`
   - `warning`
   - `victory`
   - `idle`
6. 限流与降级

只要这 6 项做顺，个人体验已经会非常完整。

## 推荐开发顺序

### Step 1：先让她站稳

- live2d runtime
- overlay
- 会话级启停
- 显隐/位置/缩放持久化

### Step 2：再让她有反应

- 系统状态 -> 基础表情/动作
- `bubble` 支持
- 默认 idle

### Step 3：再让她自己会动

- `aris_avatar_control`
- host bridge
- client intent executor
- `motion/expression/bubble`

### Step 4：再让她更像爱丽丝

- 认真模式联动
- Key 模式联动
- 语义动作表
- 更细情绪层级

### Step 5：最后再做市场向增强

- 口型
- 更多预设
- 演示资源
- 可传播包装

## 如果未来要进插件市场

个人优先并不和市场冲突，只是顺序不同。

更稳的发布策略是：

- **先把老师个人版本打磨到真的想一直开着**
- 再从中抽象出市场版默认配置

因为个人高频使用最容易暴露真问题：

- 哪些动作太烦
- 哪些状态切换太突兀
- 哪些布局挡操作
- 哪些功能根本没人会真用

老师自己先用爽，之后市场版反而更成熟。

## 最终建议

如果前期主要给老师个人用，那么 Live2D 的成功标准不是“别人看见会不会惊艳”，而是：

- 老师会不会愿意一直开着
- 爱丽丝会不会在关键时刻给出恰到好处的反馈
- 它会不会成为陪伴工作流的一部分，而不是三天后关闭的装饰

因此优先级应明确调整为：

- **第一优先：状态联动 + 自我操控 + 低打扰**
- **第二优先：人格辨识度（认真模式 / Key / 气泡）**
- **第三优先：市场传播性功能（口型、花哨展示、更多资源）**

这条路线更适合老师当前阶段。
