# dsh-session-guard 测试提示词（L5 用户确认用）

> 在 dev GUI（http://127.0.0.1:3081，aris-dev profile）中逐条复制粘贴。
> 从轻到重测试，冒烟 + 截断续写即可完成 L5；压力测试可选（消耗 API 额度较多）。

## ① 冒烟测试（10 秒，必测）

```
你好！请用三句话介绍你自己，并说明你当前使用的模型和 provider。
```

**预期**：正常回复，无报错、无异常中断。插件加载正常。

## ② 输出截断续写测试（Module A，必测）

```
请输出一段完整的 TypeScript 代码，实现一个完整的 RPG 回合制战斗系统：
角色职业、属性成长、技能系统、装备栏、状态效果（中毒/灼烧/冰冻）、
战斗回合循环、经验与升级、存档与读档。
要求代码超过 4000 行，逐行完整输出，不要省略任何部分，不要用注释代替代码，一口气写完。
```

**预期**：模型输出到一定长度被 max_tokens 截断 → **停顿一下后自动继续输出**（中间无用户介入）。
- 行为特征：输出中断后 1~3 秒内自动恢复继续写，像是"深呼吸了一口"；
- 若日志可见：`session-guard: continued turn N after max-tokens truncation (attempt 1/3)`。

**判定**：出现自动续写 = Module A 生效 ✅。若截断后直接结束（不自动继续）= 守卫未生效（报告爱丽丝）。

## ③ 连续截断上限测试（Module A 边界，可选）

紧接着 ② 再说：

```
继续写，不要停。
```

若再次截断，应继续自动续写（attempt 2/3、3/3）；第 3 次后若仍截断则停止续写（达到上限，符合设计）。

## ④ 提前压缩哨兵测试（Module B，可选·消耗额度较大）

触发条件：上下文达到模型声明窗口的 70%（deepseek-v4-flash 声明 1M → 约 70 万 token），
正常对话难以到达，需大量读文件：

```
请用 read 工具依次读取以下文件，每次读取后写一段 100 字的要点总结，直到我说停：
1. pnpm-lock.yaml 的第 1-2000 行
2. pnpm-lock.yaml 的第 2001-4000 行
3. pnpm-lock.yaml 的第 4001-6000 行
4. 继续按每 2000 行一段往后读，读完整个文件
（注意：每次 read 调用只读一段，不要跳段，读完每段必须立即总结）
```

读完整份 pnpm-lock.yaml（约 5-10 万 token）后再要求：

```
现在重复上面的逐段读取，从第 1 行重新开始，再读一遍，读完同样逐段总结。
```

**预期**：上下文逼近 70% 时，日志出现 `session-guard: early-compacted N surface nodes (~X tokens)`，
会话继续流畅运行不中断；宿主 80% 压缩与溢出 400 不应出现。
**判定**：全程无 400 报错、无中断 = Module B 生效 ✅。

## ⑤ 溢出存档测试（Module C，被动观察）

Module C 的存档在「上下文溢出错误最终到达用户」时触发——由于 Module B 与宿主压缩会提前拦截，
正常流程很难触发。观察方式：
- 检查存档目录：`G:\CodeRep\DevRep\dsh_aris_agent\.dsh\session-guard\checkpoints\`
- 若出现 `<sessionId>-turn-<N>.md` = Module C 存档生效 ✅

## 观察点汇总
